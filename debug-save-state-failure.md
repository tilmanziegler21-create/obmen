# Debug Session: save-state-failure

Status: OPEN

## Symptom
- После отправки заявка не сохраняется.
- ID группы города не сохраняется.
- В UI все еще видны подписи "Доступно USDT" и "Доступно налички", которые нужно убрать.

## Hypotheses
1. Запись `data/state.json` падает на сервере из-за ограничений файловой системы.
2. Заявка создается, но затем теряется при повторном чтении или перезаписи состояния.
3. Фронтенд после сохранения перезапрашивает устаревшее состояние и визуально скрывает успешную запись.
4. Маршруты `/api/orders` и `/api/admin/cities/:id` возвращают ошибку, но без достаточных runtime-следов.
5. Остатки подписей в UI находятся в переводах/компонентах отдельно от основного дефекта сохранения.

## Plan
- Добавить runtime-инструментацию без изменения бизнес-логики.
- Воспроизвести сохранение города и создание заявки.
- Собрать доказательства и подтвердить/опровергнуть гипотезы.
- После подтверждения причины внести минимальный фикс.

## Evidence
- Локальный `PUT /api/admin/cities/1` возвращает `ok: true` и сохраняет `groupChatId: "-1001234567890"` в `data/state.json`.
- Локальный `POST /api/orders` возвращает `ok: true` и включает созданную заявку в `state.orders`.
- В `data/state.json` после воспроизведения присутствуют и `groupChatId`, и созданные заявки.
- Debug Server доступен, но автоматическая отправка instrumentation-событий из sandbox-процесса в него не фиксируется; для текущего цикла использованы прямые runtime-ответы API и состояние файла.

## Hypothesis Status
- A: Локальная запись `data/state.json` падает на файловой системе — REJECTED для локального окружения.
- B: Заявка создается, но теряется при записи состояния — REJECTED для локального окружения.
- C: Фронтенд может терять свежую заявку из-за повторного `fetchInitialData()` после успешного `POST /api/orders` — CONFIRMED как правдоподобный UI-риск, исправлено.
- D: Сохранение `groupChatId` на продакшене ломается не в коде маршрута, а в окружении/деплое/хранилище — INCONCLUSIVE, но остается основной гипотезой для боевой среды.
- E: Подписи `Доступно USDT / налички` идут из отдельного UI-блока — CONFIRMED, удалено.
